## What I Learned

Documentation is not follow-up work for AI infrastructure. For skills, agent workflows, and governance patterns, clear instructions are part of the implementation because they define how people and tools will use the system.

## Pattern Worth Reusing

Start with the smallest useful agentic shape. A deterministic script or single tool-using "claw" is often better than a broad agent. Escalate to workflows or bots only when the problem actually needs model-driven control flow.

## Tooling or Agent Insight

Evaluation needs to sit beside governance. Policies and allowlists say what should be allowed; evals tell you whether the system still works after prompt changes, model changes, or tool changes.

## Decision or Tradeoff to Watch

Cross-platform portability should be deliberate, not automatic. It is useful for audit and comparison work, but new team-facing skills should use the primary platform's strengths unless reach across tools is a real requirement.

## Practical Recommendation

Before authoring or reviewing an AI skill, write one paragraph that states what problem it solves and what it explicitly does not solve. That paragraph becomes the quality bar for the implementation and the review.

## Open Question

What is the right threshold for promoting a useful workflow into a more autonomous bot? The current working answer is: only when the steps cannot be enumerated in advance and the added flexibility is measurable.
